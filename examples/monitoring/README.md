# Подключение к существующему мониторингу

Установка Prometheus, Grafana, Node Exporter, Alertmanager и сеть готовятся отдельно.

Какие ошибки приводят к Telegram-уведомлениям, описано в [README проекта](../../README.md#уведомления-в-telegram).

В этом каталоге находятся переносимые примеры:

- `rules.yml` — правила для метрик PBM, отдельного восстановления и полного учения; пороги 180 секунд PITR, 26 часов полного снимка, 8 дней проверки восстановления, 20% свободного диска. `RestoreFailed` отслеживает ошибку отдельного восстановления, `RestoreStuck` — отсутствие результата за 4 часа 10 минут.
- `dashboard.json` — импортируемый дашборд Grafana; источник данных должен иметь UID `mongo-dr-prometheus` либо нужно изменить UID в JSON.
- `alertmanager.example.yml` — пример Telegram-канала с токеном из защищённого файла. Замените `chat_id`, не публикуйте токен.
- `test-alert.py` — явная отправка тестового события в локальный Alertmanager, затем его завершение.

Роль PBM раз в минуту атомарно пишет `<pbm_home>/state/metrics.prom`. Существующий Node Exporter можно настроить на чтение этого файла через textfile collector. Родительские каталоги должны быть доступны экспортеру на проход, а файл — на чтение. Учётные данные PBM и S3 читать экспортеру не требуется.

Назначьте метки `host` и `role` в настройках опроса своего Prometheus. Пример:

```yaml
scrape_configs:
  - job_name: node
    static_configs:
      - targets: ['YOUR_MONGODB_PRIVATE_IP:9100']
        labels:
          host: mongo-01
          role: source
```

Для получателя используйте `role: recovery`, для контроллера с метриками учения — `role: management`. Эти метки нужны только примерам мониторинга; роли MongoDB и PBM по ним не выбирают поведение. Правило `S3Unavailable` дополнительно умеет использовать внешний Blackbox probe, если он уже настроен.

Путь к textfile и адреса экспортеров зависят от вашей установки. На существующем стенде используется `/var/lib/prometheus/node-exporter/`, но роль PBM не устанавливает и не настраивает этот каталог. На узлах MongoDB подключите `metrics.prom`, на контроллере — `<project>/artifacts/restore.prom` и `<project>/artifacts/drill.prom`. Для отдельно перенесённой роли путь отчёта задаётся `pbm_restore_report_path`: подключайте соседний файл `.prom`. При нескольких получателях используйте отдельный путь отчёта для каждого, чтобы их результаты не перезаписывали друг друга.

## Подключение Telegram

Подключите `rules.yml` через `rule_files` в конфигурации своего Prometheus и укажите в нём адрес Alertmanager. Настройте Telegram-получатель по `alertmanager.example.yml`: замените `chat_id` на числовой ID своего чата, сохраните токен бота в отдельном файле и укажите путь в `bot_token_file`. Файл должен быть доступен процессу Alertmanager и закрыт от остальных пользователей. Отправьте боту `/start` из нужного чата. Примените конфигурацию своих Prometheus и Alertmanager.

На хосте с готовым Alertmanager, из корня проекта, выполните:

```bash
# Передать тестовую ошибку; ожидается уведомление в настроенный канал.
python3 examples/monitoring/test-alert.py
# Завершить её после получения первого сообщения.
python3 examples/monitoring/test-alert.py --resolve
```

Пример Alertmanager использует обычную группировку: сообщение о завершении может прийти после `group_interval`, по умолчанию 5 минут. HTTP 200 от API означает приём события, доставку проверяйте по сообщениям и счётчику `alertmanager_notifications_failed_total`.
