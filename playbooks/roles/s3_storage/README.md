# s3_storage

Ansible-роль для подготовки лабораторного S3-совместимого хранилища на отдельной ВМ. Устанавливает Versity S3 Gateway, создаёт бакет и отдельную учётную запись для PBM.

## Требования

- Linux x86_64 с Python 3 и systemd; лаборатория проверялась на Ubuntu 24.04 amd64.
- Права root и доступ к релизам Versity на GitHub.
- Настроенный приватный адрес ВМ и свободный порт gateway.
- Достаточное место для архива на файловой системе, где находится `s3_home`.

На стенде HTTP защищён заранее настроенным WireGuard. Роль не создаёт VPN и не настраивает публичный HTTPS. Для готового внешнего S3 эта роль не требуется: его реквизиты можно передать непосредственно роли `pbm`.

## Зависимости

Другие роли и внешние коллекции Ansible не требуются. Для распаковки релиза на ВМ нужен `tar`. Роль загружает готовый бинарный файл gateway и проверяет SHA-256.

## Переменные

Значения по умолчанию находятся в [defaults/main.yml](defaults/main.yml). Параметры стенда заданы в [group_vars/all/s3.yml](../../../inventory/group_vars/all/s3.yml).

| Переменная | Тип | По умолчанию | Назначение |
|---|---|---|---|
| `s3_bind_address` | string | Обязательная | Приватный адрес прослушивания gateway |
| `s3_endpoint` | string | Обязательная | URL gateway для административных команд; должен соответствовать адресу и порту этой ВМ |
| `s3_root_secret` | string | Обязательная | Секрет администратора: 64 шестнадцатеричных символа |
| `s3_secret` | string | Обязательная | Секрет отдельного пользователя PBM: 64 шестнадцатеричных символа |
| `s3_home` | string | `/srv/mongo-dr-s3` | Каталог хранилища: `objects/` для объектов, `iam/` для учётных записей |
| `s3_port` | integer | `19000` | Порт gateway |
| `s3_version` | string | `v1.11.0` | Версия Versity S3 Gateway |
| `s3_sha256` | string | `1f075c9dc92fef232f5b3c7465711ddc5e1b062b2b6df4a3bd246a4be5b35b52` | Контрольная сумма архива; меняется вместе с версией |
| `s3_root_access` | string | `mongo-dr-admin` | Идентификатор администратора gateway |
| `s3_access` | string | `mongo-dr-pbm` | Идентификатор пользователя PBM; должен отличаться от администратора |
| `s3_bucket` | string | `mongo-dr` | Создаваемый бакет |
| `s3_region` | string | `msk` | Имя региона S3, одинаковое у gateway и клиентов |

Секреты лаборатории создаёт `scripts/init-secrets.sh`. Внешний проект должен передавать их из защищённого источника переменных. Административный ключ gateway не нужен агентам PBM.


## Пример использования

Playbook использует группу `storage` и обязательные параметры из inventory:

```yaml
- name: Prepare laboratory S3
  hosts: storage
  become: true
  roles:
    - s3_storage
```

Параметры создаваемого хранилища и передаваемые PBM параметры должны совпадать: `s3_access` ↔ `pbm_s3_access`, `s3_secret` ↔ `pbm_s3_secret`, `s3_bucket` ↔ `pbm_s3_bucket`, `s3_endpoint` ↔ `pbm_s3_endpoint`. Роль не заполняет настройки PBM автоматически.

## Что делает роль

1. Создаёт пользователя Linux `mongo-dr-s3` и каталоги объектов и учётных записей.
2. Загружает и распаковывает проверенный релиз в `/opt/mongo-dr-s3/<версия>/`.
3. Создаёт защищённый файл `/etc/mongo-dr-s3.env` и службу `mongo-dr-s3.service`.
4. Запускает gateway и ждёт доступности его порта.
5. Через административный CLI создаёт пользователя PBM и принадлежащий ему бакет, если они отсутствуют.

Повторный запуск не очищает бакет. Создание пользователя при его отсутствии не выполняет ротацию секрета уже существующей учётной записи. Служба и пользователь Linux имеют фиксированное имя: роль рассчитана на один gateway на ВМ. Несколько gateway не образуют распределённое хранилище и не копируют данные друг другу автоматически.

## Проверка результата

На ВМ хранилища:

```bash
# Проверить, что gateway запущен.
sudo systemctl is-active mongo-dr-s3.service
```

После настройки PBM на ВМ MongoDB:

```bash
# Проверить возможность перечислить объекты архива с реквизитами PBM.
sudo /srv/mongo-dr/drctl /srv/mongo-dr/archive_s3.py
```

Вторая команда относится к путям лаборатории и при успехе завершается с кодом `0`. Она проверяет доступ на перечисление; запись и пригодность архива проверяются созданием копии и восстановлением. Сам gateway на одной ВМ не защищает от потери её диска: нужна независимая копия архива.
